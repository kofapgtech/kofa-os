# KofaOS review — 8 September 2026

Full review of the web app across security and data integrity, correctness, UX
and accessibility, and code health, against `main` at `f901762`.

**Two critical holes were found and are already closed in the live database.**
Everything else is listed below with a suggested fix. Items marked ✅ are fixed
in this branch; the rest are left for a decision.

## How things were checked, and how much to trust each finding

- **Executed** — the exploit or bug was run against the live project inside a
  rolled-back transaction, impersonating a real user. These are facts.
- **Read** — confirmed by reading the code, with the failing path traced to a
  `file:line`. High confidence, not executed.
- Anything I could not confirm is marked as such rather than asserted.

Deliverable fees and deliverable-based task assignment were **excluded** from
this review, since that feature may be removed.

---

## CRITICAL — fixed

### 1. Any signed-in member could make themselves an admin ✅ *(Executed)*

The `profiles_update` policy allows `user_id = auth.uid()` so people can edit
their own name and title. That restricts the **row** but not the **columns**,
and no trigger covered `role`. One statement from the browser console — the
same shape `useUpdateProfile` (`src/lib/queries.ts:130`) already sends —
promoted a staff account to `admin`.

Verified end to end: `role` went `staff` → `admin`, `is_admin()` then returned
true, and `pay_periods` went from 0 rows to 33. The same hole allowed
self-editing `is_active`, `is_hidden`, `employment_type`, `department_id`,
`email` and the termination fields.

**Fixed** by `supabase/migrations/20260908170000_guard_privileged_profile_columns.sql`
— a `BEFORE UPDATE` trigger pinning the administrative columns, applied to the
live project. Re-verified after the fix: staff self-promotion refused, HR
self-promotion refused, while a staff member editing their own name, an admin
setting someone's role, and HR promoting staff → dept_lead all still work.

### 2. `v_workstream_budget` ignored row-level security ✅ *(Executed)*

The view was `security_invoker = off` — the only view in the schema that was —
so it ran as its owner and bypassed RLS. Its body multiplies task hours by
`profile_rates.cost_rate`, and it carries no `org_id` predicate of its own, so
any staff member or contractor could `GET /rest/v1/v_workstream_budget` and
read every workstream's committed labour cost, derived from colleagues' pay
rates that `profile_rates` explicitly denies them. As staff: `workstream_budgets`
returned 0 rows, the view returned 3.

**Fixed** in the same migration (`security_invoker = on`). Re-verified: staff
now get 0 rows, a workstream lead still gets 3.

## HIGH

### 3. Every date column renders a day early, west of UTC ✅ *(Read, fixed)*

`new Date('2026-09-01')` parses as UTC midnight and `toLocaleDateString` then
renders it in local time — 20:00 on Aug 31 in New York. Every `DATE` column was
affected: `period_start`, `period_end`, `due_date`, `start_date`,
`target_end_date`. **A printed payroll invoice stated the wrong pay period.**

`weekRange()` in the same file always did this correctly with
`timeZone: 'UTC'`, so the codebase already knew the right pattern.

**Fixed** in `src/lib/format.ts`: `shortDate`/`longDate` detect a bare
`YYYY-MM-DD` and render it in UTC; timestamps stay local.

### 4. A task due today showed as overdue all day ✅ *(Read, fixed)*

Same root cause: `new Date(t.due_date) < new Date()` at
`src/pages/MyWork.tsx:51`, `src/components/TaskViews.tsx:537,687` and
`src/components/DeliverableCard.tsx:30`. A task due today went red at the
reader's midnight and inflated the "Overdue" count on My work.

**Fixed** with a new `isPastDue()` in `format.ts` that compares calendar dates
as strings.

### 5. Logging time didn't refresh the approval card next to it ✅ *(Read, fixed)*

`TIME_DEPENDENT_KEYS` (`src/lib/queries.ts:54`) omitted `timesheet-weeks` and
`payroll-entries`. `v_timesheet_weeks` derives its total from `time_entries`,
but the `timesheet_weeks` row is untouched by a log or delete, so realtime
never fired either. Log 3h and the grid said 7.00h while the approval card
directly below said 4.00h, indefinitely — and an approver's queue was stale too.

**Fixed** by adding both keys.

### 6. Link attachments accepted any URL scheme ✅ *(Read, fixed)*

`DeliverablePanel` stored `linkInput.trim()` verbatim and passed it to
`window.open`. A member could plant a `javascript:` or `data:` link, or a
lookalike domain, that a lead clicks during review.

**Fixed**: the scheme is validated to http(s) on save *and* again on open (rows
predate the check), a bare `example.com` is treated as https, and `noreferrer`
was added.

### 7. The invite Edge Function is dead — it queries a column that doesn't exist *(Executed)*

`supabase/functions/invite-employee/index.ts:83-88` does
`.from('profiles').select('id, org_id, role').eq('id', user.id)`. `profiles`
has no `id` column — the key is `user_id`. PostgREST errors, so **every invite
returns 403 "No profile for caller"**.

It fails closed, so this is not an escalation — but the invite feature does not
work. **Not fixed**, because the obvious repair is unsafe: `.eq('user_id', …)`
throws for anyone holding two memberships and would stamp an arbitrary `org_id`
onto the invitee. It needs to resolve the caller's *active* workspace, mirroring
`current_org_id()`. It also needs redeploying, which cannot be done from here.

### 8. Timesheet weeks are bucketed locally on the client, in UTC on the server *(Read)*

`src/pages/Timesheet.tsx:25-38` uses local-time `mondayOf`/`dateKey`, while
`format.ts:235` documents that `timesheet_weeks.week_start` is UTC. A New York
contractor logging Sunday 21:00 sees it in this week's grid; the server counts
it in next week. The grid total and the approval card below it then disagree.

**Fix:** derive the week with the existing `weekStartOf()` and bucket entries by
the UTC day of `started_at`. Not applied — it changes which week existing
entries fall into, so it wants a deliberate migration of expectations.

## MEDIUM

- **Budget planner can become unsavable.** `ProjectDetail.tsx:627-636` counts
  past draft months in `draftTotal` but filters them out of the payload, while
  the RPC requires the set to sum to `budget_amount`. Header says "$60,000 of
  $60,000 planned"; saving sends $40,000 and is rejected, with no explanation.
- **`money()` drops cents** (`format.ts:28`). The planner accepts `step="0.01"`,
  so a $0.40 shortfall renders as "**$0** unallocated" — the UI says zero and
  still refuses to balance. Changing this touches every money display, so it is
  a decision, not a clear-cut fix.
- **Two open tabs corrupt timer attribution.** `TimerContext.tsx:22,41` loads
  the running timer once with no realtime or refetch; `stop()` takes no argument
  and closes whichever entry is open — potentially the wrong task.
- **Burn-up chart silently drops the oldest entries** past a 1000-row limit
  (`queries.ts:1821`), contradicting the "Hours logged" tile on the same page.
- **Payroll blockers computed from a 500-row truncated list** (`queries.ts:1912`).
  For older periods the "Awaiting approval" chip vanishes and **Pay now** offers
  itself for unapproved time. The RPC still refuses, so no money moves — but
  finance is told the wrong thing.
- **A sent-back timesheet week is only reachable from its own week**
  (`Timesheet.tsx:90-93`), so an old rejection can block a payroll period with
  no way to resubmit.
- **HR can read any employee's files, including an executive's.** The
  `employee_attachments` table restricts HR to staff/dept_lead rows; the
  `employee-files` storage policies check only org and role, and paths are
  predictable. The bucket should mirror the table's check.
- **Contractors can read all accounts via the API** — the `non-contractor` gate
  is client-side only; `accounts_read` is just `org_id = current_org_id()`.
- **No size or MIME limits on any bucket**; all four have
  `file_size_limit = null`.
- **Modals and drawers have no focus trap, `role="dialog"` or Escape-to-close**
  (`ui.tsx:108`, `TaskViews.tsx:898`, `DeliverablePanel.tsx:250`,
  `AppShell.tsx:515`). Nothing in the app closes on Escape.
- **The kanban board has no keyboard path at all** (`TaskViews.tsx:782`) —
  status changes are mouse-drag only.
- **Query errors render as empty states.** Pages destructure `data: x = []` and
  branch only on `isLoading`, so a failed fetch reads as "you have nothing".
- **`text-ink-400` fails contrast** on cream backgrounds (4.20:1 on `cream-100`,
  3.88:1 on `cream-200`, against a 4.5:1 floor). `ink-500` passes.
- ✅ **Icon-only close buttons had no accessible name** — fixed in four places.

## LOW

Deleting a time entry and removing an hour allocation skip the `ConfirmDialog`
every other delete uses. Tables lack `scope="col"`. Buttons have no
`focus-visible` ring. Filenames are not slugified into storage keys.
`profiles_read` exposes colleagues' `email` and termination fields to everyone.
The `avatars` bucket is public. Leaked-password protection is off in Supabase
Auth.

## Code health

The codebase is in good shape: no `any`, no `dangerouslySetInnerHTML`, RLS
genuinely doing the work nearly everywhere. The highest-payoff items:

1. **Route the 12 hand-formatted `.toFixed()` sites through `format.ts`.** One
   is a real bug: `AdminEmployees.tsx:914` reimplements `fileSize()` without the
   MB tier, so a 5MB file reads "5000 KB" there and "5.0 MB" elsewhere.
2. **Split `TaskViews.tsx` (1,765 lines) at line 898.** List/board/calendar
   above, detail panel below, connected only by a `Task | null` and a callback —
   a genuinely low-risk split.
3. **Collapse the three identical attachment hook families** in `queries.ts`
   (~150 lines that are one pattern three times).
4. **Generate Supabase types in CI** as a tripwire — every query result is
   currently `as SomeType` against hand-written interfaces.

Naming drift (`department` vs `workstream`) is real but the DB column rename
isn't worth it; renaming only the TypeScript identifiers is compiler-checked
and free.

**No tests exist.** The four worth writing first are all pure functions where a
silent wrong answer costs money: `weekStartOf`, `groupPayrollEntries`, the
period-overlap check in `usePayrollApprovalBlockers`, and the `burnTone`
thresholds.

## Checked and clean

The client portal holds up: the RPCs are `SECURITY DEFINER` with
`search_path=''`, both check revocation and expiry, the review RPC re-verifies
the deliverable belongs to that token's account, tokens are 192 bits, and the
payload carries a rounded percentage rather than any money. Payroll gates are
database-backed, and `record_payroll_payment` computes the amount itself rather
than trusting the client. No XSS vectors. No secrets in client code or logs.
