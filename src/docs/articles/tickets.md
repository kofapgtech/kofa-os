When the docs do not answer it, raise a ticket. **Submit a ticket** is pinned at the foot of the sidebar on every screen, so you never have to go looking for it.

## Raising one

The page describes itself: "Raise a request with the admin team and follow it here."

Give it a clear title, pick the area it concerns, and describe what happened — the guidance in [Getting help](/docs/getting-help) on what to include applies exactly here. You can attach a file, which is usually a screenshot.

## Following it

Your own tickets are listed on the same page, so this is also where you check on something you raised last week rather than asking again.

A ticket moves **Open → In progress → Resolved → Closed**. When an admin marks yours resolved, you get the last word: **Close** it if the answer worked, or **Reopen** it if it did not. A closed ticket is locked.

Comments run down the ticket, and you are notified when someone replies.

> [!NOTE] A ticket is private
> Only you and the admins can see one you raised — it is not visible to your workstream or to anyone else in the workspace. That is enforced in the database, not just hidden in the screen, so a ticket is a reasonable place to raise something awkward.

## If you are an admin

The sidebar button reads **Manage tickets** instead, and takes you to the queue — "Every request raised in this workspace." — with filters, internal notes that the person who raised it cannot see, and the status controls.
